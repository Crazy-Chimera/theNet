# Relation Contract — Iteration 4\n\n## Purpose\n\nRelation is the first structural link after Genesis. It records a directed, explicit relation between two existing subjects without mutating either subject.\n\n## Input\n\n- source_id: non-empty string identifying the relation source.\n- target_id: non-empty string identifying the relation target.\n- kind: non-empty string describing the relation.\n- created_at: non-empty string identifying when the relation was created.\n\n## Output\n\nAn immutable Relation containing:\n- id\n- source_id\n- target_id\n- kind\n- created_at\n- version = 1\n\n## Identity\n\nid is the SHA-256 digest of the canonical relation payload:\ncreated_at, kind, source_id, target_id, version\n\nThe canonical representation must be deterministic.\n\n## Invariants\n\n1. Source and target IDs must be non-empty strings.\n2. Relation kind must be non-empty.\n3. Creation timestamp must be non-empty.\n4. Same valid input produces the same relation ID.\n5. Different relation-defining input produces a different ID.\n6. Output is immutable.\n7. Relation creation does not mutate Genesis or any other object.\n8. Relation is directed: reversing source and target changes identity.\n9. Relation has no external-service dependency.\n10. Relation does not itself imply verification, consensus, contribution, memory, convergence, or meaning.\n\n## Boundary\n\nGenesis creates entities. Relation links entities. Later modules may verify, score, store, or interpret relations; Relation itself remains a minimal structural primitive.
